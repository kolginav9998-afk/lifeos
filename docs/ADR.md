# Решения по архитектуре (ADR)

Короткие записи: что решили, почему и чем это проверяется. Если решение меняется, добавляй новую запись, а не стирай старую.

## ADR-1. Один код для сайта и Android-приложения
- **Решение:** веб-приложение (PWA) одно; Android-APK собирается из тех же файлов через Capacitor.
- **Почему:** нужно, чтобы на телефоне и в браузере всё работало одинаково, а любое изменение проверялось один раз.
- **Следствия:** native-возможности (уведомления, файлы) подключаются через `platform.js` и работают, только если доступны; всё остальное одинаково.
- **Проверка:** `scripts/build-web.sh` собирает сайт и APK из одних файлов; `pages.yml` и `apk.yml` запускают одни и те же тесты.

## ADR-2. Журнал событий как единственный формат данных
- **Решение:** всё хранится записями `{id, type, ts, payload, source, confidence, evidence}`. Новые типы только добавляются, существующие поля не переименовываются.
- **Почему:** синхронизация, экспорт и откат проще, когда данные одинакового вида; старые записи читаются всегда («обновление не должно стирать данные»).
- **Следствия:** все типы описаны в [EVENTS.md](EVENTS.md) (из `registry.js`); записи незнакомых типов (от более новой версии) сохраняются и не мешают; копия из более новой версии открывается только после обновления приложения.
- **Проверка:** `tests/compat.test.mjs` (старые форматы), `tests/registry.test.mjs` (реестр совпадает с кодом и документом).

## ADR-3. Без сборщика, без внешних библиотек и адресов
- **Решение:** обычные ES-модули без бандлера; в коде нет `innerHTML`, `eval`, внешних адресов и сетевых вызовов, кроме клиента сервера синхронизации и офлайн-кэша.
- **Почему:** безопасность (строгая политика CSP), прозрачность кода для проверки, работа без интернета.
- **Следствия:** интерфейс строится через `el()`; списки с «необязательными» элементами собираются через `fill()` (иначе `null` превращается в текст).
- **Проверка:** `tests/static.test.mjs` (запрещённые конструкции, внешние адреса, `null` в `replaceChildren`), `tests/size.test.mjs` (бюджет размера), `tests/deps.test.mjs` (нет циклов, соблюдены слои).

## ADR-4. Шифрование на устройстве, сервер не видит данные
- **Решение:** пароль превращается в ключ (PBKDF2-SHA256, 600 000 итераций), записи шифруются AES-256-GCM; сервер синхронизации хранит только зашифрованные записи.
- **Почему:** в данных здоровье, деньги, дневник и мысли.
- **Следствия:** забытый пароль восстановить нельзя; резервные копии шифруются отдельным паролем; потеря кода восстановления аккаунта означает потерю доступа.
- **Проверка:** `tests/crypto.test.mjs`, `tests/e2e-security.mjs` (на диске нет открытого текста), `tests/server.test.mjs`, `tests/e2e-sync.mjs`.

## ADR-5. Сайт выкладывается только после проверок в настоящем браузере
- **Решение:** `pages.yml`: модульные тесты → сценарии в Chromium → публикация. Красные проверки не пускают обновление на сайт.
- **Почему:** пользователь не программист, проверка на телефоне дорогая, а ошибки в данных недопустимы.
- **Следствия:** каждая новая функция получает тест логики и сценарий; на телефоне пользователь проверяет только то, чего автотест проверить не может (уведомления, вид, жесты).
- **Проверка:** `docs/RELEASE.md`, `docs/CHECKLIST.md`.

## ADR-6. Аналитика осторожная: связь, а не причина
- **Решение:** сравнение только с самим собой (личная норма: медиана и MAD), поправка на множественные сравнения, интервалы для оценок, формулировки «связь, не доказанная причина», дни болезни исключаются.
- **Почему:** на малых данных легко увидеть закономерность там, где её нет.
- **Следствия:** выводы появляются после нескольких недель отметок; есть личные эксперименты (фазы A/B в случайном порядке) для проверки гипотез.
- **Проверка:** `tests/stats.test.mjs`, `tests/bt-analytics.test.mjs`.

## ADR-7. Никаких диагнозов и лечебных советов
- **Решение:** приложение считает и показывает цифры, а советы даёт только общие (сон, движение, обращение к врачу) и всегда как предложение. Тесты не диагностика и не IQ.
- **Почему:** безопасность пользователя и честность.
- **Следствия:** в тексте нет слов «диагноз/лечение» как обещаний; при долго низком настроении приложение направляет к близким и специалистам.
- **Проверка:** тексты в `reflect.js`, `thoughts.js`, `prevent.js`, `emergency.js` и тесты на их содержание.

## ADR-8. Внутри приложения нет ИИ: разбор по правилам и подтверждение человеком
- **Решение:** «умный ввод» понимает фразы по правилам и предлагает действие; сохраняется только после нажатия.
- **Почему:** приватность (ничего не уходит наружу), работа без интернета, предсказуемость.
- **Следствия:** для работы с ИИ-репетитором в курсах есть готовые запросы для копирования; данные в чужие сервисы приложение не отправляет.
- **Проверка:** `tests/capture.test.mjs`, статическая проверка сетевых вызовов.

## ADR-9. Постоянный ключ подписи APK
- **Решение:** APK всегда подписывается одним и тем же ключом (отпечаток проверяет сборка), «последний APK» лежит по постоянной ссылке.
- **Почему:** Android ставит обновление поверх, только если подпись совпадает; иначе данные пришлось бы вводить заново.
- **Проверка:** шаг «Проверить, что подпись — наш постоянный ключ» в `apk.yml`.

## ADR-10. Миграции формата вместо «ломающих» изменений
- **Решение:** новые типы и поля только добавляются; если старые записи нельзя читать как есть, повышается `SCHEMA_VERSION` и пишется шаг в `migrate.js`. Копии старых версий проходят миграции при восстановлении, копии новее приложения отклоняются.
- **Почему:** данные должны переживать любые обновления; единственное место, где старый формат встречается снова, — файл резервной копии.
- **Следствия:** миграция не меняет исходный список и проверяется на примере старой копии; результат миграции снова проходит проверку записей.
- **Проверка:** `tests/r39.test.mjs` («миграции…»), `docs/RELEASE.md` («Если меняется формат данных»).

## ADR-11. Часы и память устройства: только подсказки
- **Решение:** приложение замечает записи «из будущего», откат часов назад и нехватку места, но ничего не исправляет само.
- **Почему:** время и место принадлежат системе телефона; тихая «починка» порядка записей хуже явного предупреждения. Неверные часы ломают порядок записей, напоминания и синхронизацию.
- **Проверка:** `devicetime.js`, `storageinfo.js` (чистая логика) и тесты в `tests/r39.test.mjs`. Файл `clock.js` — другое: логические часы синхронизации.

## ADR-12. Загрузка архива по умолчанию только добавляет
- **Решение:** загрузка архива добавляет новые записи и не трогает уже имеющиеся. Если ничего не затирается, загрузка проходит сразу. Записи, отличающиеся от имеющихся, заменяются только по явному выбору, после показа того, что внутри. Режим «только проверить» ничего не меняет.
- **Почему:** главный риск восстановления из старой копии: тихо вернуть старые версии поверх новых правок. Для человека без технических навыков безопасный вариант должен быть вариантом по умолчанию.
- **Следствия:** настройки в архиве применяются сами только на пустом устройстве; в архив входят лишь настройки внешнего вида и времени напоминаний, без привязанных к устройству.
- **Проверка:** `tests/archive.test.mjs`, `tests/e2e-archive.mjs`, `tests/fuzz.test.mjs`.

## ADR-13. Навык подтверждается карточками, а не отметкой «пройден»
- **Решение:** навык из урока предлагается, когда урок пройден и выучено не меньше 80% его карточек (коробка 4 и выше: повторение раз в две недели и реже). Всё остальное человек добавляет сам.
- **Почему:** «точно изучил» нельзя определить по одной отметке. Интервальные повторения дают проверяемый признак.
- **Проверка:** `tests/skills.test.mjs`.

## ADR-14. Второе окно: подтягиваем записи, а не блокируем
- **Решение:** окна одного приложения считают друг друга (`BroadcastChannel`) и после записи в одном окне другие перечитывают данные. Окно не блокируется: просто видна подсказка.
- **Почему:** блокировка вторым окном раздражает и ломается при зависшем окне; общая картина данных безопаснее. Запись идёт по одной записи, поэтому окна не затирают друг друга целиком.
- **Проверка:** `tests/safety.test.mjs`, `tests/e2e-r311.mjs`.
