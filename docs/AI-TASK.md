# Шаблон постановки задачи ИИ-помощнику (для разработки Life OS)

Скопируй шаблон, замени тексты в угловых скобках и отправь. Чем точнее критерии приёмки, тем меньше правок. Правила проекта в одном месте: [ADR.md](ADR.md), [QUALITY.md](QUALITY.md), [RELEASE.md](RELEASE.md), типы данных в [EVENTS.md](EVENTS.md), слова в [GLOSSARY.md](GLOSSARY.md).

```
Цель (одно предложение):
<что должно стать лучше для пользователя>

Контекст:
- Проект: Life OS, сайт и Android из одного кода, ES-модули без сборщика, репозиторий lifeos, ветка main.
- Затрагиваемые файлы: <список файлов или «найди сам и перечисли»>
- Связанные типы записей: <из docs/EVENTS.md или «новый тип»>

Ограничения (обязательно):
- Без innerHTML, eval, внешних адресов и сетевых вызовов; интерфейс строится через el(), списки с возможным null через fill().
- Данные только добавляются: старые записи читаются всегда; новый тип записи добавь в registry.js и перегенерируй docs/EVENTS.md и docs/ER.md.
- Логика отдельно от экрана: чистая логика в модулях без ui.js, store.js, db.js (это проверяет tests/deps.test.mjs).
- Тексты интерфейса на русском, простым языком, без диагнозов и лечебных советов.
- Личные тексты не попадают в выгрузку для аналитики.

Критерии приёмки:
1. <проверяемое поведение 1>
2. <проверяемое поведение 2>
3. Есть модульные тесты логики (tests/*.test.mjs) и сценарий в браузере (tests/e2e-*.mjs), если меняется экран.
4. npm test и npm run test:e2e проходят полностью; в консоли браузера нет ошибок.
5. Документы обновлены: GUIDE.md (что нового), CHECKLIST.md (шаги проверки на телефоне).

Не делать:
- Не менять формат существующих записей.
- Не добавлять зависимости.
- Не трогать <файлы, которые нельзя менять>.

Ответ:
- Коротко: что сделано, какие файлы, результат проверок.
- Честно: что проверено автоматически, а что нужно проверить на телефоне.
```

## Как проверять результат
1. Запусти `npm test` и `npm run test:e2e` и убедись, что обе команды зелёные.
2. Прочитай изменения по файлам: нет ли лишнего и нет ли обходных путей (отключённых тестов, пропущенных проверок).
3. Выпуск и откат: [RELEASE.md](RELEASE.md).
