# Общие правила для помощников (глобальное обновление R4.0)

Прочитай целиком, потом делай своё задание. Файл временный: перед выпуском его уберут.

## Проект
Life OS: личное приложение для владельца без технического опыта, говорящего по-русски. Один код на чистом JavaScript (ES-модули, без сборщика и фреймворков) в `/home/user/lifeos`: сайт (PWA, GitHub Pages) и Android-приложение (Capacitor 7: проект Android создаёт сборка командой `cap add android` и скрипт `scripts/patch-android.py`). Весь интерфейс по-русски, простыми словами. Данные: журнал записей `{id,type,ts,payload,source,confidence,evidence}` на устройстве (IndexedDB, по желанию шифрование паролем) и сквозное шифрование при синхронизации с сервером на одного человека (Cloudflare Worker, `server/`).
Сначала прочитай: `README.md`, `docs/ADR.md` (решения), `docs/RELEASE.md` (сборка и тесты), `docs/QUALITY.md`, `tests/helpers.mjs` и один браузерный тест (`tests/e2e-gate.mjs`), чтобы понять стиль.

## Где работать
Ты работаешь в своей изолированной копии (git worktree) ветки `global-update`. Первым делом: `git checkout -b team/<твоё-имя>` и `ln -s /home/user/lifeos/node_modules node_modules` (никогда не делай npm install). Node 22; Playwright и Chromium уже стоят (`require('playwright')` работает). Машина на 4 ядра общая с другими помощниками: юнит-тесты `npm test` (около 10 секунд), браузерные тесты по одному файлу (`node tests/e2e-<имя>.mjs`). Весь набор `npm run test:e2e` НЕ запускай. Если браузерный тест упал по времени, повтори один раз, прежде чем считать его сломанным.

## Правила и ловушки этого кода
- Никакого `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `eval`. DOM строится функцией `el(тег, свойства, ...дети)` из `ui.js` (пропускает пустые дети) и `fill(узел, ...дети)` (никогда не `replaceChildren(null)`). Свойство `list` у полей ввода ставится через `setAttribute`. Состояние правки сбрасывай ДО `store.save` (сохранение перерисовывает экран). `id` элементов уникальны во всех исходниках (проверяет тест). Существующие `id` и классы, которые используют тесты, не менять.
- Типы записей только ДОБАВЛЯЮТСЯ (не переименовывать и не удалять); старые данные читаются всегда. Новый тип: строка в `REGISTRY` в `registry.js` (label, group, module, privacy, analytics, fields) и перегенерация документов: `node -e "import('./registry.js').then(r=>{const fs=require('fs');fs.writeFileSync('docs/EVENTS.md',r.registryMarkdown()+'\n');fs.writeFileSync('docs/ER.md',r.erMarkdown()+'\n')})"`. Тест реестра ищет в исходниках `type: '...'`, поэтому ключ `type:` нельзя использовать ни для чего, кроме типа записи.
- Слои (`tests/deps.test.mjs`): модули логики (всё, кроме `view-*`, `ui.js`, `store.js`, `db.js`, `platform.js`, `vault.js`, `app.js`, `app-sync.js`, `notify.js`, `errlog.js`) не импортируют интерфейс, хранилище и экраны; экран может импортировать только свои дочерние блоки `view-<экран>-<часть>.js`; никто не импортирует `app.js`. Бюджет размера: все файлы сайта вместе не больше 1,4 МБ, каждый не больше 64 КБ.
- Настройки, привязанные к устройству (`prefs.js`, DEFAULTS), которые не должны ехать в архиве, добавляй в список `deviceBound` в `tests/archive.test.mjs`; переносимые настройки идут в `PREF_RULES` в `archive.js` с проверкой значений.
- `clock.js` — логические часы синхронизации: не перезаписывать. Протокол сервера нельзя менять несовместимо со старыми клиентами.
- У сайта строгая политика безопасности (CSP): `script-src 'self'`, в статической разметке нет встроенных скриптов и атрибутов `style`; стили, выставленные из JS (`el.style`), можно. В тестах, где нужно внедрить скрипт, открывай контекст с `bypassCSP`. Тесты по умолчанию собирают приложение с `LIFEOS_REQUIRE_ACCOUNT=0` (без экрана входа); `tests/e2e-gate.mjs` показывает, как собрать с экраном входа и локальным сервером.
- Цвета только через токены в начале `style.css`; `tests/r313.test.mjs` проверяет контраст WCAG пар цветов; уважай `prefers-reduced-motion`.
- Данные пользователя прежде всего. Никаких медицинских диагнозов и утверждений.
- Коммить в свою ветку (можно несколько коммитов); в конце каждого сообщения коммита две строки: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` и `Claude-Session: https://claude.ai/code/session_01TqN67aWgyY244xTWQqCZZg`. Ничего не пушить, ветки `main` и `global-update` не трогать, запросы на слияние не создавать.
- Общие файлы НЕ править: `version.js`, `changelog.js`, `docs/GUIDE.md`, `docs/CHECKLIST.md`, `docs/IDEAS.md`, `docs/COUNCIL.md`, `package.json`, `package-lock.json`, `.github/workflows/*` (кроме случаев, когда это прямо разрешено в твоём задании). Нужное для них пиши в итоговом отчёте в разделе SHARED-FILE NOTES: пункты для changelog (по-русски, не меньше двух, каждый длиннее 10 символов), шаги проверки на телефоне (по-русски), короткий абзац для GUIDE (по-русски), имена новых e2e-файлов для списка `test:e2e`.
- Бюджет: у владельца ограниченный лимит использования. Работай экономно: сначала `grep`, читай фрагменты, а не целые большие файлы; объединяй вызовы инструментов; не повторяй полные прогоны без нужды; предпочитай небольшие проверенные изменения. Что нельзя проверить без настоящего телефона, описывай, а не выпускай вслепую.

## Итоговый отчёт (коротко, до 60 строк)
Ветка и sha последнего коммита; добавленные и изменённые файлы; добавленные тесты и их результаты; риски и неизвестное; SHARED-FILE NOTES; какие конфликты слияния ожидать.
