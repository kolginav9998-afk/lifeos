# Сервер синхронизации: свой, бесплатный, надолго

Нужен, чтобы **один логин и пароль работали на всех устройствах** (телефон, приложение, браузер) и чтобы данные переживали любые обновления и даже потерю телефона.

## Текущее состояние
- Сервер развёрнут на Cloudflare Workers (бесплатный тариф): `https://lifeos-sync.kolginav9998.workers.dev`. Это Worker `lifeos-sync` с базой Durable Object.
- Адрес записан в `config/sync.json`, поэтому сайт и приложение подставляют его сами (с версии R3.11.1): «Ещё → Аккаунт» сразу показывает адрес.
- Пока аккаунт не создан, регистрация закрыта **кодом установки** (секрет `SETUP_CODE` на самом сервере). Код выдан владельцу лично и в репозитории не хранится. Заменить его можно в панели Cloudflare: Workers & Pages → `lifeos-sync` → Settings → Variables and Secrets. После создания аккаунта регистрация закрывается сама, и код больше не нужен.
- Обновить код сервера можно повторной публикацией (способ Б ниже или команда `npx wrangler deploy` в папке `server/cloudflare` с ключом Cloudflare). Секреты и данные при этом сохраняются.

## Как это устроено и что видит сервер
- На сервере хранится **только зашифрованное**. Шифрование происходит на твоём устройстве, ключ получается из пароля. Сервер не знает ни пароль, ни ключ.
- На сервер уходит не пароль, а **ключ входа**, посчитанный из него. Даже если сервер взломают, прочитать записи без пароля нельзя (нужен подбор пароля, поэтому делай его длинным).
- Сервер видит: сколько у тебя записей, их размер и время изменения. Не видит: что это за записи.
- Аккаунт **один**: регистрация открыта, пока он не создан, потом закрывается.
- Забыл пароль → **код восстановления** (его показывают один раз при создании аккаунта). Без пароля и без кода данные не вернуть никому, в том числе мне.
- Приложение работает и без сервера. Записи всегда лежат и на самом устройстве; сервер — общий «склад» для синхронизации.

## Что понадобится
Бесплатный аккаунт Cloudflare (почта и пароль, **банковская карта не нужна**). Сервер работает на Cloudflare Workers с встроенной базой (Durable Objects, SQLite). На бесплатном тарифе этого хватает с огромным запасом для одного человека; платить не придётся, пока не превысишь лимиты (для личного дневника это недостижимо).

## Способ А. Проще всего: через панель Cloudflare и GitHub (без токенов)
1. Зарегистрируйся на https://dash.cloudflare.com и подтверди почту.
2. В панели открой **Workers & Pages → Create → Import a repository** (подключить Git). Разреши доступ к GitHub и выбери репозиторий `lifeos`.
3. Настройки проекта:
   - **Project name:** `lifeos-sync`
   - **Root directory:** `server/cloudflare`
   - **Deploy command:** `npx wrangler deploy` (оставь по умолчанию)
4. Нажми **Save and Deploy** и подожди пару минут.
5. Открой `https://lifeos-sync.<твой-поддомен>.workers.dev/v1/status`. Должен показаться текст, начинающийся с `{"app":"lifeos-sync"…`. Это и есть адрес сервера.

Дальше сервер обновляется сам при каждом изменении в репозитории.
> Названия кнопок в панели Cloudflare иногда меняются. Если что-то не совпало, пришли мне скриншот.

## Способ Б. Через GitHub Actions (автоматически из репозитория)
1. Токен: открой https://dash.cloudflare.com/profile/api-tokens (раздел **My Profile → API Tokens**) → **Create Token** → у шаблона **Edit Cloudflare Workers** нажми **Use template** → **Continue to summary** → **Create Token**. Скопируй токен (длинная строка, начинается с `cfut_`): он показывается один раз.
2. **Account ID**: в панели **Workers & Pages**, блок **Account Details**, кнопка копирования рядом с **Account ID** (или поиск панели: «Copy account ID»).
3. В GitHub: репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Создай два секрета: `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`.
4. Вкладка **Actions → server → Run workflow**. Через пару минут в итоге запуска появится адрес сервера.

## Способ В. Свой сервер или компьютер
Нужен Node 22+ и HTTPS (например, через Caddy или Cloudflare Tunnel):
```bash
PORT=8787 DB_PATH=./lifeos-sync.db ALLOWED_ORIGINS=https://kolginav9998-afk.github.io,https://localhost node server/node/server.js
```

## После развёртывания
1. **Сразу создай аккаунт**: первый, кто зарегистрируется, становится владельцем. Чтобы закрыть сервер от посторонних до этого момента, можно задать секрет `SETUP_CODE` (в панели Cloudflare: Settings → Variables and Secrets). Тогда при создании аккаунта нужно будет ввести этот код.
2. В приложении: **Ещё → Аккаунт** → вставь адрес → «Проверить сервер» → «Создать аккаунт».
3. **Запиши код восстановления** (на бумагу или в менеджер паролей). Он покажется один раз.
4. На остальных устройствах: тот же адрес → «Войти».
5. Пришли мне адрес сервера: я пропишу его в `config/sync.json`, и он будет подставляться на всех устройствах сам (а защитная политика сайта станет пускать только к нему).

## Что делать, если…
- **Забыл пароль:** «Аккаунт → Забыл пароль» → введи код восстановления и новый пароль. Остальные устройства войдут заново.
- **Потерял телефон:** войди с другого устройства и смени пароль (старые сессии закроются).
- **Сервер пропал или сброшен:** данные остались на устройствах. На устройстве с самыми свежими данными выйди из аккаунта, создай его заново на новом сервере (тем же паролем), на остальных выйди и войди снова. Данные объединятся.
- **Хочу всё стереть на сервере:** «Аккаунт → Безопасность → Удалить аккаунт на сервере». На устройствах данные останутся.
- **Адрес workers.dev не открывается** в твоей сети: напиши мне, подключим другой хостинг (код сервера одинаковый для любого).

## Ограничения и честные оговорки
- Шифрование не проходило независимый аудит. Для личных данных этого достаточно, но не рассчитывай на него как на единственную защиту очень опасных секретов.
- Метки времени у записей нужны для слияния: если на двух устройствах отредактировать одну запись одновременно, **побеждает более поздняя правка** целиком (без построчного слияния).
- Ключ входа и пароль защиты на устройстве **один и тот же пароль**.
- Сервер нельзя использовать как «облачный бэкап для всех»: он рассчитан на одного пользователя.
